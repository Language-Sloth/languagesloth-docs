# CLAUDE.md

Notes for Claude Code working in this repo.

## What this is

A Quartz v4 static site that publishes Markdown notes under `content/` to GitHub Pages at <https://language-sloth.github.io/languagesloth-docs/>. The site is the Language Sloth community's governance documentation.

## Repo layout

- `content/` — site content. URL structure mirrors folder structure. `content/index.md` is the homepage.
- `quartz/` — framework source. Don't edit unless customizing the framework itself.
- `quartz.config.ts` — site config (title, baseUrl, plugins).
- `quartz.layout.ts` — page layout. Left sidebar is currently empty; right sidebar has graph, TOC, and backlinks.
- `.github/workflows/deploy.yml` — CI that builds and deploys on push to `main`.
- `public/` — build output. Gitignored; generated by CI.

## Working with content

- Markdown is Obsidian-flavored. Use `[[Page name]]` for internal links, `[[Page name|alias]]` for custom text.
- Front matter is optional but supported (`title:`, `tags:`, etc.).
- The folder name `Language Sloth` becomes `Language-Sloth` in URLs — Quartz slugifies paths.

## Deployment

Push to `main` → GitHub Actions workflow runs `npx quartz build` → deploys `public/` to GitHub Pages. No manual builds. Don't commit `public/`.

To check workflow status: <https://github.com/Language-Sloth/languagesloth-docs/actions>.

## Local preview

```sh
npx quartz build --serve
```

Serves on <http://localhost:8080> with file watching.

## Known pitfalls

### Mermaid diagrams

**Don't use `%%` comments inside ```` ```mermaid ```` blocks.** Quartz's Obsidian-flavored markdown plugin strips `%%`-comment lines from code blocks (Obsidian uses `%%` for hidden comments), corrupting the diagram source and causing render errors. Just remove the comments or convert them to mermaid `note` syntax.

### Subgraph declarations

In mermaid `flowchart`, declare subgraphs *before* drawing edges to them. Writing `A --> SUBGRAPH_ID` before `subgraph SUBGRAPH_ID[...]` creates `SUBGRAPH_ID` as a plain node first, then the later `subgraph` line fails.

### Folder index pages — never `Foo.md` next to `Foo/`

When you have a section overview AND subpages, put the overview at `Foo/index.md`, not `Foo.md` sitting next to a `Foo/` subfolder. The latter makes Quartz emit two URLs for the same content (`Foo.html` and `Foo/index.html`) and the relative wikilink math goes off-by-one for one of them, causing 404s when users land on the folder URL.

### Always set `title:` on `index.md` files

Without `title:` frontmatter, an `index.md` page renders its H1, breadcrumb, and `<title>` as the literal word "index". Always include:

```yaml
---
title: Display Name For This Page
---
```

### Cross-folder wikilinks

If a wikilink target lives in a different folder, prefer the path-explicit form: `[[Language Sloth/Foo/Bar|Bar]]`. The bare `[[Bar]]` form uses `markdownLinkResolution: "shortest"` and can pick the wrong slug when folder names and file names collide.

### Bold in mermaid labels

Avoid `**bold**` inside node labels. The markdown processor may transform it before mermaid sees it. Use plain text in quoted labels: `NODE["Label text"]`.

## Don't do these

- Don't commit `public/` — CI generates it.
- Don't delete `LICENSE.txt` — Quartz's MIT license requires keeping it since `quartz/` ships with the repo.
- Don't change Pages source in repo settings — it's set to "GitHub Actions" and the workflow handles deployment.
